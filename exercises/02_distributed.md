# 第 2 次课：并行配置与故障排查

目标：在原始源码上自行重现分布式推理的问题，完成定位和修复。

1. 记录双卡通信拓扑，说明 TP、DP Attention 的请求、权重与通信参与关系，并区分其他并行方式的用途。
2. 从第一课配置建立双卡实验分支，设置普通 TP 配置与 DP Attention 配置；每次仅修改与该实验有关的参数，使用独立 runtime 和日志目录。
3. 分别测试纯文本、单图、多图，以及文字/图片混合并发。记录是否启动、是否返回、是否超时，并保留各 rank 的第一处异常、堆栈及请求时间。
4. 对失败最小化输入，沿调用链检查张量形状与通信时序，形成可证伪的假设。用新的证据验证假设，再提交最小修复。
5. 将同一套请求再次运行，覆盖不同 batch、不同图像数量与空闲 rank 等边界。确认原来可用的配置仍可使用。

提交到 `submissions/02_distributed/`：

- `matrix.csv`：配置 × 请求类型 × 运行结果。
- `failure/`：原始失败日志与最小输入。
- `diagnosis.md`：调用链、张量/通信图、证据与根因。
- 自己的修复提交及 `regression.md`，记录修改前后的结果。

验收：能用同一输入重现修改前失败、修改后成功；根因必须对应源码和各 rank 证据。不得仅用增大超时或关闭原实验功能解释为修复成功。
