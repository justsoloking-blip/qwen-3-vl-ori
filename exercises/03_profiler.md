# 第 3 次课：Profiler 分析与优化优先级

目标：从实际时间线中发现瓶颈，为第四课选择优化对象。

1. 保持第一课的负载定义，将性能测量与 Profiler 采集分开进行。记录预热、输出长度、并发及采样范围。
2. 采集各 rank 的 CPU/GPU trace，使用统计脚本生成 CSV 与 JSON；在时间线工具中确认 trace 与运行日志属于同一实验。
3. 分析前端、prefill、decode，以及计算、通信、拷贝、布局变换的时间分布。截取时间线并标注推断依据。
4. 对耗时最高的算子检查调用次数、输入形状和上下游依赖，判断可能受计算、访存、同步或调度影响。名称分类需人工核对。
5. 按预计影响、实现成本与风险，列出至少三个优化候选。说明需要什么对照实验才能判断有效。

提交到 `submissions/03_profiler/`：

- `trace-manifest.json`：trace 位置、SHA256、rank、采样条件与对应代码提交。
- `kernels.csv` 与自己绘制的算子分布图。
- `timeline.png`：标注后的时间线。
- `bottlenecks.md`：瓶颈、证据、尚未证实的推断与候选优先级。

验收：区分算子累加时间、活动区间并集与请求端到端耗时；不得把无 GPU 活动直接等同于 SM 利用率，或把 Profiler 开销当作线上时延。
